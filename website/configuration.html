Declarative settings

Configuration

One JSON document controls concurrency, timeouts, attempt limits, gate policy, research, memory, and Git behavior. Unknown keys, wrong types, and out-of-range values are rejected at load time.

Worked example

A complete configuration file

Stored as project-local configuration and honored only after project trust is established.

{
  "version": 1,
  "agents": {
    "maxConcurrency": 2,
    "timeoutMinutes": 30,
    "models": {
      "researcher": "inherit",
      "planner": "inherit",
      "developer": "inherit",
      "testWriter": "inherit",
      "testRunner": "inherit",
      "reviewer": "inherit",
      "committer": "inherit"
    }
  },
  "gates": {
    "maxConsecutiveFailures": 5,
    "maxTotalAttempts": 20,
    "requireCleanFinalTree": true
  },
  "research": {
    "webEnabled": true,
    "recordSources": true
  },
  "memory": {
    "enabled": true,
    "updateOnSuccess": true,
    "reviewRequired": true,
    "redactSecrets": true
  },
  "git": {
    "worktreeRoot": "adjacent",
    "retainFailedRuns": true,
    "autoCommit": true,
    "allowHistoryRewrite": false
  }
}
Reference

Every key, type, default, and constraint

KeyTypeDefaultConstraints & notes
versioninteger1Schema version. Must be 1; other major versions are rejected, not migrated silently.
agents.maxConcurrencyinteger21–4. Caps simultaneous subagents; the developer and test writer run in parallel at the default.
agents.timeoutMinutesinteger301–120. Child pi process timeout; expiry is treated as an agent failure and retried as infrastructure.
agents.models.<role>string"zai/glm-5.3-flash:max"Per role of researcher, planner, developer, testWriter, testRunner, reviewer, committer. Accepts "inherit" or provider/model[:thinking]. A value present in the file is an explicit selection and takes precedence over the package's role-prompt pin; absent keys fall through to the pin, then the default. See per-subagent model selection.
gates.maxConsecutiveFailuresinteger51–10. Consecutive failures on any single gate counter before the planner is engaged.
gates.maxTotalAttemptsinteger20≥ 10 and ≥ maxConsecutiveFailures. Hard ceiling across all attempts to prevent infinite loops.

research.webEnabledbooleantrueEnables automatic web research; false restricts the researcher to the repository.

Subagent models

Defaults and per-role overrides

Every subagent defaults to zai/glm-5.3-flash:max — GLM-5.3-Flash at maximum thinking. Set agents.models.<role> to any supported provider model id, or to "inherit" to reuse the session's model for that role. A value written into the file is an explicit selection and takes precedence over the package's role-prompt pin — see per-subagent model selection.

Per-role

Assign stronger or cheaper models where they matter — for example, a deeper model for the planner and reviewer while runners stay fast.

inherit

Defer to whatever model the user's pi session is running, keeping cost and behavior aligned with the interactive session.

Thinking level

The :max suffix requests maximum thinking. Levels are part of the model string, so each role's reasoning budget is explicit and inspectable.

Per-subagent models

Per-subagent model selection

Each of the seven roles — researcher, planner, developer, testWriter, testRunner, reviewer, committer — resolves its model independently from your own pi setup. The winning spec is passed to the child pi process at spawn time.

First match wins

  1. Explicit selection — any value present in .gx-dev/config.json under agents.models.<role>, including "inherit". Written by /gx-dev models or scripts/models.mjs set.
  2. Role-prompt pin — the model: frontmatter in the package's agents/*.md for that role.
  3. Built-in default — zai/glm-5.3-flash:max for every role.

Omitting a role is not the same as unpinning it: absent keys fall through to the pin, while an explicit "inherit" overrides the pin and delegates to the session.

The :thinking suffix

Specs are provider/model with an optional :thinking suffix — for example ollama-cloud/deepseek-v4-flash:0731:max.

  • Levels: off, low, medium, high, xhigh, max.
  • The level is applied only when the selected model supports reasoning; other models simply run without it.
  • The suffix is part of the string, so each role's reasoning budget stays explicit and inspectable in /gx-dev config.

Three surfaces, one store

  • /gx-dev models — the interactive picker (see the TUI reference).
  • /gx-dev models set <role> <spec> — a direct one-line write; /gx-dev models show prints the resolved chain per role.
  • node scripts/models.mjs <show|list|set|unset|get> — the same store from a shell or CI script.

Every surface writes agents.models.<role> atomically; unset removes the key so the pin or default applies again.

Terminal session

$ node scripts/models.mjs show
researcher   inherit                  explicit (config)
planner      zai/glm-5.3-flash:max    pin (planner.md)
reviewer     ollama-cloud/deepseek-v4-flash:0731:max
             ↑ explicit (config)
committer    zai/glm-5.3-flash:max    default

$ node scripts/models.mjs set committer zai/glm-5.3-flash:low
$ node scripts/models.mjs unset researcher
$ node scripts/models.mjs get reviewer
$ node scripts/models.mjs list

A mixed fleet

Only roles listed in the config are explicit. Here the reviewer gets a heavyweight reasoning model, the researcher rides the session's model, and the rest stay on the fast default:

{
  "version": 1,
  "agents": {
    "models": {
      "researcher": "inherit",
      "planner": "zai/glm-5.3-flash:max",
      "developer": "zai/glm-5.3-flash:max",
      "testWriter": "zai/glm-5.3-flash:max",
      "testRunner": "zai/glm-5.3-flash:max",
      "reviewer": "ollama-cloud/deepseek-v4-flash:0731:max",
      "committer": "zai/glm-5.3-flash:max"
    }
  }
}

Reading the fleet

  • researcher — explicit "inherit": spawned without --model, using whatever the interactive session runs.
  • reviewer — a heavyweight model with the :max suffix; adversarial review is where reasoning depth pays.
  • Everyone else — set to the default explicitly, keeping the file self-documenting.
  • Drop any key (unset) and that role falls back to the package pin, then the default.
Validation is structural; availability is advisory. At load time a selection must be "inherit" or a well-formed provider/model[:thinking] string — anything else is a config error. Availability is different: models come from your own pi setup (pi --list-models and the model registry), so an unmatched selection only warns in /gx-dev models show and the picker — it never blocks a run. See troubleshooting for mismatch fixes.
Semantics

Flag groups in depth

Gates limits

  • maxConsecutiveFailures applies independently to test, review, and integration counters.
  • Infrastructure retries are tracked separately and never consume the budget.
  • maxTotalAttempts bounds every attempt in the run, including retries.
  • requireCleanFinalTree keeps the final commit free of unrelated changes.

Memory flags

  • enabled gates both evidence capture and promotion.
  • updateOnSuccess ties proposals to passing gates.
  • reviewRequired enforces the reviewer-verified promotion pipeline.
  • redactSecrets scrubs credential-shaped strings from memory writes.

Git flags

  • worktreeRoot controls isolation location; custom paths must sit outside the repository.
  • retainFailedRuns preserves diagnosis material at the cost of disk.
  • autoCommit commits after all gates pass; rollback instructions are always recorded.
  • allowHistoryRewrite cannot be enabled — see validation below.
Trust & validation

How configuration is validated

Validation rules

  • Unknown keys are rejected — typos never silently no-op.
  • Types are exact: booleans are not coerced from strings.
  • Numeric ranges are enforced as listed above.
  • git.allowHistoryRewrite: true is a hard error, by design.
  • Run /gx-dev config or /gx-dev doctor to see full validation output.

Trust ordering

  • Project-local configuration is honored only after project trust is established.
  • Untrusted projects run on package defaults only.
  • Project-local agent definitions face the same trust gate, so repository content cannot redefine gates.
