Implementation roadmap

Delivery plan

Eleven evidence-driven phases move gx-dev from a deterministic state engine to a hardened, distributable pi package.

RoadmapTestingScopeDefinition of done
Phases

Build assurance before autonomy

Phase 1

Foundation

Package scaffold, schemas, state machine, persistent event store, core commands, and fake-agent harness.

Exit: deterministic transitions survive restart.
Phase 2

Subagent runtime

Isolated pi subprocesses, streaming JSON, prompts, cancellation, timeout, usage, truncation, and structured completion.

Exit: every specialist runs independently with validated output.
Phase 3

Git isolation

Repository discovery, worktrees, branches, checkpoints, staging integration, cleanup, recovery, and new projects.

Exit: parallel changes integrate without prematurely modifying the user tree.
Phase 4

Research and planning

Automatic web research, provenance, sanitization, approvals, acceptance criteria, and verification contracts.

Exit: approved artifacts are versioned and hash-linked.
Phase 5

Parallel development

Developer/test-writer concurrency, moderated questions, independence controls, and structured handoff.

Exit: neither worker can inspect the other's uncommitted work.
Phase 6

Test and review loops

Preflight, command discovery, evidence, failure ownership, five-failure replanning, review, and documentation update.

Exit: every gate transition has machine-verifiable evidence.
Phase 7

Committer

Merge assessment, final verification, automatic commit, result report, rollback, and cleanup policy.

Exit: one traceable commit contains no unrelated changes.
Phase 8

Compounding memory

Evidence store, wiki, schema validator, provenance, pins, reservations, lint, and redaction.

Exit: later workflows reuse reviewed knowledge rather than raw capture.
Phase 9

TUI polish

Dashboard, progress, questions, evidence, theme-aware rendering, and narrow-terminal accessibility.

Exit: users can monitor and control a complete workflow in TUI.
Phase 10

Documentation application

Multi-page static site, diagrams, search, light/dark mode, responsive navigation, and accessibility.

Exit: build, link, responsive, theme, and accessibility checks pass.
Phase 11

Hardening and release

Threat review, cross-platform tests, package installation, migrations, examples, and release automation.

Exit: npm, Git, and local pi package installation work.
Verification

Test the orchestrator like infrastructure

Unit

Transitions, counters, schemas, path containment, redaction, Git parsing, provenance, pins, and reservations.

Integration

Temporary Git repos, dirty trees, detached HEAD, worktree conflicts, retries, resume, cancel, commit, and rollback.

Protocol

Fake pi event streams covering success, malformed output, timeout, abort, partial output, model errors, and truncation.

TUI

Narrow/wide terminals, keyboard use, dashboard updates, modals, line width, and theme invalidation.

Documentation

Build, links, landmarks, heading order, contrast, responsiveness, screenshots, and offline assets.

End-to-end

TypeScript, Python, empty projects, repeated failures, malicious research, concurrent memory, and rollback.

Version one

Strong local core before distributed expansion

Included

  • Local Git repositories
  • Empty-project bootstrapping
  • Isolated child pi processes
  • Git worktrees
  • Automatic web research
  • Reviewed Markdown memory
  • TUI workflow management
  • Automatic final commits
  • Static documentation application

Deferred

  • Remote workers and distributed queues
  • Pull-request creation
  • Team memory servers
  • Browser workflow control
  • Autonomous deployment
  • Vector memory as a requirement
  • Force pushes and history rewriting
Completion contract

Definition of done

  • Installable pi package exposes documented /gx-dev commands.
  • Seven specialist agents run in isolated contexts with restricted tools.
  • Developer and test-writer work concurrently in separate worktrees.
  • All communication is moderated by the orchestrator.
  • Requirements and architecture receive mandatory user approval.
  • Test and review gates have independent five-failure escalation.
  • The planner receives complete failure evidence.
  • Reviewer-verified documentation is included before commit.
  • The committer safely commits without final approval.
  • Existing and empty projects are supported.
  • Runs can pause, resume, cancel, recover, and roll back.
  • Web research records provenance and treats content as untrusted.
  • Raw capture remains separate from reviewed memory.
  • Secrets and destructive operations are guarded.
  • Automated tests and documentation checks pass.
