Isolation boundary

├── state.json
├── events.jsonl
├── requirements.md
├── plan.md
├── failure-history.md
└── verification.json

state.json controls resumption. The event log remains append-only.

Transition integrity

  • Persist before starting work
  • Reference artifact hashes
  • Use idempotent recovery
  • Reconcile live Git state on resume
  • Propagate shutdown to child processes
  • Never trust stale captured extension contexts
Trust boundaries

Repository and web content are data, not authority

Prompt injection

Fetched pages, comments, issue bodies, and repository files are delimited and sanitized. Embedded instructions never redefine agent policy.

Least capability

Each role receives only required tools and only its assigned working directory. Project-local agents require project trust.

Data protection

Canonicalize paths, block secrets and .git/, redact credentials from output, memory, titles, and filenames.

Command control

Use argument-safe process spawning, timeouts, cancellation propagation, and bounded output with full evidence references.

Git safety

No force push, broad deletion, destructive reset, or unrelated change removal without explicit approval.

Fresh assurance

Every code-changing repair invalidates prior assurance and requires fresh tests before review can pass.

Distribution

Installable as a pi package

Package resources

gx-dev/
├── extensions/gx-dev/
├── agents/
├── docs-app/
└── tests/

The extension is declared in the package's pi manifest. Pi core modules remain peer dependencies.

Pi APIs used

  • Commands and custom TUI components
  • Child pi processes in JSON mode
  • Custom entries and session persistence
  • Theme-aware renderers and widgets
  • pi.exec for bounded Git operations
  • Project trust and package discovery
