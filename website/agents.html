gx-dev / Agents
Specialist boundaries

Agent contracts

Each agent has an explicit purpose, restricted tools, structured output, and a clear prohibition against approving its own contribution.

Seven specialists

Roles and boundaries

O

Orchestrator

Application-owned conductor and user liaison.

  • Owns state, routing, recovery, and failure counters.
  • Answers minor reversible questions.
  • Escalates material decisions.
  • May fix narrow operational issues.
Cannot bypass gates
R

Researcher

Builds the repository and domain evidence base.

  • Inspects project structure and conventions.
  • Searches the web automatically with provenance.
  • Identifies uncertainty, risk, and questions.
  • Drafts acceptance criteria.
Read-oriented
P

Planner

Creates implementation and independent testing plans.

  • Defines architecture and file-level tasks.
  • Defines verification and rollback contracts.
  • Receives complete five-failure histories.
  • Replans holistically or asks the user.
Cannot implement
D

Developer

Implements production behavior in an isolated worktree.

  • Follows the approved implementation plan.
  • Reports deviations and limitations.
  • Responds to test and review findings.
  • Does not inspect independent uncommitted tests.
Production worktree
T

Test writer

Independently tests requirements and public contracts.

  • Covers positive, negative, boundary, and regression cases.
  • Prioritizes externally visible behavior.
  • Records assumptions and coverage gaps.
  • Does not change production code.
Test worktree
G

Test runner

Integrates branches and executes the first assurance gate.

  • Reviews separate diffs for obvious defects.
  • Runs project-native verification commands.
  • Records exact evidence and classifies ownership.
  • Cannot weaken valid tests to pass.
Gate authority
A

Adversarial reviewer

Assumes green tests may still hide defects.

  • Scrutinizes correctness, security, quality, and risk.
  • Produces severity-ranked evidence.
  • Updates documentation only after review succeeds.
  • Proposes verified durable memory.
Independent review
C

Committer

Produces the reversible, traceable final result.

  • Assesses repository merge conventions.
  • Runs the final verification contract.
  • Adds only intended files.
  • Records commit hash and rollback instructions.
No history rewriting
Communication model

Agents speak through structured packets

{
  "status": "complete",
  "summary": "...",
  "artifacts": ["..."],
  "questions": [],
  "assumptions": [],
  "risks": [],
  "recommendedNextState": "PLAN"
}

Protocol guarantees

  • Schema validation before transition
  • Role-specific required evidence
  • One retry with schema feedback
  • Questions routed by severity
  • No prose-only completion
  • No agent-selected gate result
Anti-collusion

Moderation prevents false consensus
