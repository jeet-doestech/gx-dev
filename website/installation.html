Installation

gx-dev distributes as a pi package. Install it through pi's package install flow — from the registry, a Git URL, or a local path — grant project trust on first run, and start orchestrating.

Three sources

Install methods

All methods use pi's package install flow; the package manifest declares the gx-dev extension, and pi core modules remain peer dependencies.

01 / REGISTRY

pi package registry

Install the published package through pi's package install command:

pi install gx-dev

The canonical pi package-install flow; consult pi --help for your version's exact syntax.

02 / GIT URL

From a Git URL

Install directly from a repository to track a branch or prerelease:

pi install https://github.com/<org>/gx-dev.git

Useful for pinning to a revision before a registry release.

03 / LOCAL PATH

From a local path

Point pi at a local checkout for development:

pi install /path/to/gx-dev

Changes take effect after restarting pi; ideal while hacking on the extension.

Onboarding

First run

What happens

  1. Start pi inside your project; the gx-dev extension registers its /gx-dev commands.
  2. Pi prompts for project trust before any project-local configuration or agents are honored.
  3. On first use, gx-dev creates .gx-dev/ for run state and scaffolds .gx-dev/memory/ when memory promotion first succeeds.
  4. Run /gx-dev start "<your story>" — intake and research begin immediately.

What is created

.gx-dev/
├── runs/<run-id>/
│   ├── state.json
│   ├── events.jsonl
│   └── evidence/
└── memory/

Everything lives inside the project; nothing is written outside it except the adjacent worktree root.

Maintenance

Upgrade & removal

Upgrading

  1. Finish or pause running workflows.
  2. Repeat the package install command with the newer version (registry, Git URL, or local path).
  3. Restart pi so the upgraded extension loads.
  4. Run /gx-dev doctor; persisted run state is versioned and resumes across upgrades.

Removing

  1. Finish or cancel active runs.
  2. Run /gx-dev cleanup to remove worktrees and run branches.
  3. Uninstall via pi's package removal flow and restart pi.
  4. .gx-dev/ — evidence and reviewed memory — is retained unless you delete it deliberately.
