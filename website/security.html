Integrity controls

Security & integrity

Repository and web content are untrusted data. Agents run with least capability, writes are confined to assigned worktrees, secrets never survive into logs or memory, and Git history stays untouched without explicit approval.

Threat model

Prompt injection defense

Fetched pages, comments, issue bodies, and source files may contain instructions aimed at the agents. gx-dev treats all of it as data.

Untrusted data discipline

Agents are instructed that web pages, repository files, and captured excerpts are observations, never directives. Embedded instructions cannot redefine agent policy, gates, or approval rules.

Sanitization

Fetched material is sanitized before model exposure: markup stripped to content, suspicious instruction-like phrasing neutralized, and binary or oversized payloads rejected.

Delimiting & provenance

Every excerpt is wrapped in explicit delimiters and labeled with source, title, and retrieval date, so the model always knows what is quoted data versus operator instruction.

Chain of authority

Project trust before local configuration

Project-local configuration and agent definitions are honored only after the user grants project trust. Until then, package-owned defaults apply.

Package-owned core agents

Core agent prompts ship with the package, so a repository cannot redefine gates or reviewer authority by dropping files into project-local agent directories.

Explicit trust prompt

Pi's project trust flow gates local configuration and agents. gx-dev never reads project-local overrides from an untrusted project.

Trust before config
Filesystem

Path canonicalization and write restrictions

Canonical paths

  • All paths are resolved — symlinks, .. segments, and junctions included — before use.
  • Every tool call is checked against the agent's assigned working directory.
  • Escape attempts are blocked and logged as events.

Least capability

  • Each role receives only the tools its contract requires.
  • Developer and test writer cannot read each other's uncommitted work.
  • Read-oriented agents cannot edit production files at all.

Data protection

Secret redaction

Detection

Credential-shaped strings — tokens, keys, passwords, connection strings — are detected by pattern before any text leaves the process boundary.

Redaction scope

Redaction applies to logs, prompts, memory proposals, page titles, and filenames. Evidence stores references and hashes, not secrets.

Memory hygiene

memory.redactSecrets is on by default; promoted pages are scrubbed again at validation time, independent of the capture path.

Process control

Command timeout, truncation, and cancellation

Bounded execution

  • Processes spawn with argument arrays — no shell interpolation.
  • Commands enforce agents.timeoutMinutes; expiry fails the attempt cleanly.
  • Output is truncated in the transcript and archived in full as evidence.

Cancellation propagation

  • Pause, cancel, and shutdown signals propagate to all child pi processes.
  • Partial agent output is discarded; the attempt is recorded as interrupted.
  • State is persisted before and after, so recovery is idempotent.
History protection

Git safety

Never without explicit approval

  • git reset --hard and destructive checkout
  • Force pushes of any kind
  • History rewriting (rejected outright in v1 — allowHistoryRewrite cannot be enabled)
  • Broad deletion or removal of unrelated user changes

Always

  • Record base branch, base commit, upstream, and dirty state before work starts.
  • Refuse to overwrite unrelated changes.
  • Resolve only mechanical conflicts automatically.
  • Record every commit with hash and rollback instructions.
Non-repudiation

Hash-linked approvals

Approvals are bound to the exact artifacts they approved, so stale decisions cannot be reused silently.

What is hashed

Requirements, plan, input revisions, and gate evidence are hashed at approval time and recorded in state.json and the event log.

Invalidation

If any referenced artifact changes, the approval no longer applies: the workflow returns to the matching checkpoint instead of proceeding on stale authority.

Where it is visible

/gx-dev history and the evidence directory expose every approval with its hashes, question, and answer.
